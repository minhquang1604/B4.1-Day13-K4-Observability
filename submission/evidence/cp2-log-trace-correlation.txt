## Cơ chế liên kết hai chiều

log -> trace : mỗi log "response_sent" mang field trace_id, dán thẳng vào Langfuse.
trace -> log : generation metadata mang correlation_id, grep ngược ra log của request.

Vì sao correlation_id nằm ở generation metadata chứ không phải trace metadata:
test công khai của Lab Coach (tests/test_agent_prompt_trace.py:52) khóa cứng
trace metadata == đúng 4 key prompt_name/prompt_label/prompt_version/prompt_source.
Thêm key vào đó sẽ làm hỏng test của giám khảo, nên đặt ở generation —
vẫn hiện đầy đủ khi mở span trong trace waterfall.

## 4. Cách tra ngược khi điều tra (dùng ở CP3)

# tu log ra trace
jq -r 'select(.correlation_id=="req-cafe1234") | .trace_id' data/logs.jsonl
# tu trace ra toan bo vong doi request
jq -c 'select(.trace_id=="b5441568099a53cbd4e92534ca2b35d6")' data/logs.jsonl
# request cham nhat kem trace_id de mo Langfuse
jq -c 'select(.event=="response_sent") | {correlation_id,trace_id,latency_ms}' data/logs.jsonl \
  | jq -s 'sort_by(-.latency_ms)[:5]'

## Bàn giao cho người làm prompt versioning (KHÔNG thuộc scope role A)

Langfuse kết nối được, nhưng prompt chưa được tạo trên project:

  Error while fetching prompt 'day13-chat-label:production': status_code: 404,
  body: {'message': "Prompt not found: 'day13-chat' with label 'production'",
         'error': 'LangfuseNotFoundError'}
  Returning fallback prompt ... due to fetch error

Hệ quả: trace hiện ghi prompt_source=local-fallback, prompt_version=local-v1.
Phải tạo prompt "day13-chat" v1/v2 và gắn label "production" trên Langfuse thì
CP2 mới có evidence prompt version thật (xem docs/PROMPT_VERSIONING.md).

Ngoài ra LANGFUSE_HOST trong .env đang để trống; SDK tự fallback về
https://cloud.langfuse.com nên vẫn chạy, nhưng nên điền tường minh.
